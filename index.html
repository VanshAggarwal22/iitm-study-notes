# 1. Linux Filesystem & Inode Mechanics

# The Inode (Index Node)

An inode stores metadata about a file. Crucially, the file name is NOT stored in the inode (it is stored in the directory entry that maps the name to an inode number).

  • Stored in Inode: File type, permissions, owner UID, group GID, file size, timestamps (access atime, modification mtime, change ctime), link count, pointers to data blocks.
  • Commands:
  • ls -i : Displays the inode number.
  • stat : Full dump of inode attributes.
  • df -i: Filesystem inode usage (can run out of inodes even if disk space remains).

# Hard Links vs. Symbolic (Soft) Links

FeatureHard Link (`ln target linkname`)Symbolic Link (`ln -s target linkname`)
**Inode**Shares the **exact same inode** as targetHas its **own distinct inode**
**Data Blocks**Points directly to target's data blocksStores target's **path string** in its block
**Link Count**Increments target inode's link count by 1Target link count is **unaffected**
**Deleting Target**File data persists! Link count decrements by 1Link becomes a **broken / dangling link**
**Directories**Cannot hard link directories (prevents loops)Can link directories
**Cross-Filesystem****Cannot** span across different filesystems**Can** span across different filesystems/mounts
IMPORTANT
If a file has 3 hard links and you rm the original file, the data blocks remain intact until link count drops to 0 AND all open file descriptors close.

# 2. Permissions & `umask` Arithmetic

# Octal Representation

  • Read (r) = 4, Write (w) = 2, Execute (x) = 1.
  • Triplets: [Owner][Group][Others]
  • chmod 755 file.sh $\rightarrow$ rwxr-xr-x
  • chmod 644 file.txt $\rightarrow$ rw-r--r--

# Symbolic Notation

  • Users: u (user/owner), g (group), o (others), a (all).
  • Operators: + (add), - (remove), = (set exact).
  • chmod u+x,g-w file
  • chmod go=r file (sets group and others to read-only).

# The `umask` Formula

umask determines default permissions of newly created files and directories.

  • Base permissions:
  • New Directory base: 0777 (rwxrwxrwx)
  • New Regular File base: 0666 (rw-rw-rw-) — *Execution bit is never granted by default for security.*
  • Calculation Rule:

$$\text{Effective Permission} = \text{Base} \mathbin{\&} \sim(\text{umask}) \quad \approx \quad \text{Base} - \text{umask}$$

(Bitwise NOT operation; simple subtraction holds whenever bits do not borrow).

# High-Yield Examples:

  • If umask = 022:
  • Directory: $777 - 022 = 755$ (rwxr-xr-x)
  • File: $666 - 022 = 644$ (rw-r--r--)
  • If umask = 027:
  • Directory: $777 - 027 = 750$ (rwxr-x---)
  • File: $666 - 027 = 640$ (rw-r-----)
  • If umask = 077:
  • Directory: $777 - 077 = 700$ (rwx------)
  • File: $666 - 077 = 600$ (rw-------)

# 3. Standard Streams & Redirection

  • 0: stdin (Standard Input)
  • 1: stdout (Standard Output)
  • 2: stderr (Standard Error)

# Redirection Operators

  • cmd > file: Overwrite stdout to file.
  • cmd >> file: Append stdout to file.
  • cmd < file: Read stdin from file.
  • cmd 2> file: Overwrite stderr to file.
  • cmd 2>> file: Append stderr to file.
  • cmd > file 2>&1: Combine both stdout and stderr into file (classic POSIX).
  • cmd &> file or cmd >& file: Bash shorthand for combining stdout and stderr.
  • cmd 2> /dev/null: Discard errors silently.
  • cmd1 | cmd2: Pipe stdout of cmd1 to stdin of cmd2 (stderr is NOT piped unless redirected with |& or 2>&1 |).
  • tee file: Writes output to both stdout AND one or more files (tee -a for append).

# 4. Text Processing Power Tools

# `grep` (Global Regular Expression Print)

  • grep -i: Case-insensitive search.
  • grep -v: Invert match (print non-matching lines).
  • grep -c: Count matching lines only.
  • grep -n: Prefix matching line with its 1-based line number.
  • grep -l: List file names with matches (stops scanning file upon first match).
  • grep -w: Match whole words only.
  • grep -E (or egrep): Use Extended Regular Expressions (ERE).
  • grep -o: Print ONLY the matching string parts, one per line.

# `sort` & `uniq`

  • sort -n: Numerical sort (sorts 10 after 2, unlike lexicographical sort).
  • sort -r: Reverse order.
  • sort -k : Sort on specific key/column (e.g. sort -k 2,2).
  • sort -t : Specify field separator (e.g. sort -t: -k3,3n /etc/passwd).
  • sort -u: Sort and remove duplicates.
  • uniq: Requires sorted input!
  • uniq -c: Prefix lines by the number of occurrences.
  • uniq -d: Output only repeated/duplicate lines.
  • uniq -u: Output only unique lines (lines that appeared exactly once).

# `cut`, `paste`, `tr`

  • cut -d',' -f2,4 data.csv: Extract fields 2 and 4 separated by comma.
  • cut -c1-10 file.txt: Extract characters 1 to 10.
  • paste -d',' f1 f2: Merges lines of files side-by-side separated by delimiter.
  • tr 'a-z' 'A-Z' < file: Translates lowercase to uppercase (reads stdin only!).
  • tr -d '0-9': Delete all specified characters.
  • tr -s ' ': Squeeze consecutive spaces into a single space.

# `head`, `tail`, `wc`

  • head -n 5 file: First 5 lines.
  • head -n -5 file: All lines except the last 5 lines.
  • tail -n 5 file: Last 5 lines.
  • tail -n +5 file: From line 5 to end of file.
  • tail -f file: Follow growing file in real time.
  • wc -l: Count lines (\n).
  • wc -w: Count words.
  • wc -c: Count bytes (-m for characters).

# 6. Advanced Shell Commands: `find` & `sed`

# `find` Command

Syntax: find [path] [predicates] [actions]

  • Predicates:
  • -name "*.log" (case sensitive), -iname "*.log" (case insensitive).
  • -type f (regular file), -type d (directory), -type l (symlink).
  • -size +10M (greater than 10MB), -size -1k (less than 1KB).
  • -mtime -7 (modified within last 7 days), -mtime +30 (modified over 30 days ago).
  • -perm 755 (exact permissions).
  • Actions:
  • -exec cmd {} +: Runs cmd passing all matching files as batch arguments (efficient!).
  • -exec cmd {} \;: Runs cmd once per found file.
  • -delete: Delete matching files directly.

# `sed` (Stream Editor)

Syntax: sed [options] 'address command' file

  • Substitution: sed 's/pattern/replacement/g' file
  • g: Global (all occurrences per line).
  • 2: Replace only 2nd occurrence per line.
  • p: Print matched line (used with sed -n 's/.../.../p').
  • Deletion:
  • sed '5d' file: Delete line 5.
  • sed '1,3d' file: Delete lines 1 to 3.
  • sed '/^#/d' file: Delete comment lines starting with #.
  • sed '/pattern/!d' file: Delete lines NOT matching pattern (equivalent to grep).
  • In-place modification: sed -i.bak 's/foo/bar/g' file.txt

# 7. Process Execution, Subshells & Environment

  • cmd &: Run process in background (prints job number and PID $!).
  • $$: Current shell process ID (PID).
  • $!: Process ID of most recently backgrounded command.
  • $?: Exit status of last foreground command (0 = success, non-zero = error).
  • Subshell ( cd /tmp && ls ): Runs inside a separate child process. Working directory and environment variable modifications do NOT affect the parent shell.
  • Command Grouping { cd /tmp; ls; }: Runs in the current shell context (semicolon and trailing space before } required).
  • Environment vs. Shell Variables:
  • VAR="val": Local shell variable (not inherited by child processes/subshells).
  • export VAR="val": Exported environment variable (inherited by child processes).
  • printenv / env: Lists exported environment variables.
  • set: Lists ALL shell variables, environment variables, and functions.

# Vi / Vim Quick Reference

  • Command mode to Insert mode: i (insert before cursor), a (append after cursor), o (open new line below).
  • Deleting text: dd (delete current line), 7dd (delete 7 lines), dw (delete word), x (delete character).
  • Saving & Exiting: :w (save), :q (quit), :wq or :x or ZZ (save and quit), :q! (quit without saving).
  • Jump to line: : (e.g. :7 goes to line 7), G (end of file), gg (start of file).

# 1. DBMS Fundamentals & Data Independence

  • Data Redundancy & Inconsistency: Primary drawbacks of flat-file systems resolved by DBMS through centralization and normalization.
  • Physical Data Independence: Ability to modify physical schema (storage devices, indexes, access paths) without altering conceptual/logical schemas or application programs.
  • Logical Data Independence: Ability to alter logical schema (adding columns, tables) without changing external views or existing queries (harder to achieve).
  • Relational Model Terminology:
  • Relation $\leftrightarrow$ Table
  • Tuple $\leftrightarrow$ Row / Record
  • Attribute $\leftrightarrow$ Column / Field
  • Domain $\leftrightarrow$ Set of permissible atomic values for an attribute
  • Degree (Arity) $\leftrightarrow$ Number of attributes (columns)
  • Cardinality $\leftrightarrow$ Number of tuples (rows)

# 2. Integrity Constraints & Foreign Keys

1. Domain Constraints: Values must be atomic and match column data types (e.g. Age > 0).

2. Entity Integrity: Primary Key attributes cannot be NULL (ensures every entity is uniquely distinguishable).

3. Key Constraints: Candidate keys must be minimal super keys; primary key enforces uniqueness.

4. Referential Integrity (Foreign Key):

  • A foreign key $FK$ in child relation $R_1$ referencing primary key $PK$ in parent relation $R_2$ requires that:

For every tuple in $R_1$, $FK$ must either be NULL OR match an existing $PK$ value in $R_2$.

  • Action triggers on update/delete of referenced parent row:
  • ON DELETE CASCADE: Deletes child rows when parent is deleted.
  • ON DELETE SET NULL: Sets child foreign key to NULL (invalid if child column is NOT NULL).
  • ON DELETE RESTRICT / NO ACTION: Rejects parent deletion if child references exist.

# 3. Relational Algebra Toolkit

text
  Basic Operators:
  σ (Select Rows)  │  π (Project Cols)  │  × (Cartesian Product)
  ∪ (Set Union)    │  - (Set Difference)│  ρ (Rename)

# Core Operations

  • Selection ($\sigma_{\text{condition}}(R)$): Filters rows satisfying the condition.
  • Cardinality: $0 \le |\sigma(R)| \le |R|$.
  • Degree: Unchanged (same columns as $R$).
  • Projection ($\pi_{A_1, A_2}(R)$): Selects specified columns and removes duplicate rows (relational algebra relations are sets).
  • Cardinality: $1 \le |\pi(R)| \le |R|$ (if $|R| \ge 1$).
  • Degree: Number of attributes projected.
  • Cartesian Product ($R \times S$):
  • Cardinality: $|R \times S| = |R| \times |S|$.
  • Degree: $\text{Degree}(R) + \text{Degree}(S)$.
  • Natural Join ($R \bowtie S$): Equi-join on all common attribute names followed by projection eliminating duplicate common columns.
  • Max tuples: $|R| \times |S|$ (if common attributes contain identical values everywhere).
  • Min tuples: $0$ (if no values match on common attributes).
  • Division Operator ($R \div S$): Used for "FOR ALL" / "EVERY" queries.
  • Output has attributes $\text{Attr}(R) - \text{Attr}(S)$.
  • Tuple $t \in R \div S$ iff for every tuple $s \in S$, tuple $(t, s) \in R$.

# Cardinality Calculations:

  • If $R(A, B)$ has $n$ rows and $S(B, C)$ has $m$ rows:
  • Minimum rows in $R \bowtie S$: $0$ (no matches).
  • If $B$ is a foreign key in $R$ referencing primary key $B$ in $S$: Exactly $n$ rows (every row in $R$ matches exactly 1 row in $S$).
  • Maximum rows in $R \bowtie S$: $n \times m$ (when all $B$ values in both relations are identical).

# 4. Tuple Relational Calculus (TRC)

Non-procedural query language: $\{t \mid P(t)\}$

  • Existential Quantifier ($\exists$): "There exists at least one tuple"

$$\{t \mid t \in \text{Employee} \land (\exists d \in \text{Department})(d.\text{dname} = 'IT' \land t.\text{dept\_id} = d.\text{dept\_id})\}$$

  • Universal Quantifier ($\forall$): "For all tuples"
  • Equivalence identity:

$$\forall x \, P(x) \equiv \neg \exists x \, (\neg P(x))$$

# 5. SQL Execution Order & Advanced Syntax

# SQL Logical Query Processing Order

Writing SQL differs from how the database engine executes it:

$$\text{FROM} \longrightarrow \text{WHERE} \longrightarrow \text{GROUP BY} \longrightarrow \text{HAVING} \longrightarrow \text{SELECT} \longrightarrow \text{DISTINCT} \longrightarrow \text{ORDER BY}$$

CAUTION
Column aliases defined in SELECT cannot be referenced in WHERE or GROUP BY because SELECT is evaluated after them!

# `WHERE` vs. `HAVING`

  • WHERE: Filters individual records before aggregation. Cannot use aggregate functions (WHERE salary > 50000).
  • HAVING: Filters aggregated groups after aggregation. Uses aggregate functions (HAVING COUNT(*) > 5).

# Subquery Operators:

  • IN / NOT IN: Membership test against a list or subquery.

(Watch out for NULLs in NOT IN: if subquery returns any NULL, NOT IN evaluates to UNKNOWN/false for all rows!)

  • EXISTS / NOT EXISTS: Returns TRUE if the correlated subquery returns at least 1 row. Highly efficient because DB stops scanning on first hit.
  • ANY / SOME:
  • x > ANY (SELECT ...): Greater than the minimum of the subquery values.
  • ALL:
  • x > ALL (SELECT ...): Greater than the maximum of the subquery values.

# 6. Entity-Relationship (ER) Modeling

text
  ┌─────────────┐        ◇───────────◇        ┌─────────────┐
  │   Student   ├───(M)──┤  Enrolls  ├───(N)──┤   Course    │
  └─────────────┘        ◇───────────◇        └─────────────┘

# Components

  • Entity: An independently identifiable object in real world.
  • Weak Entity Set: An entity set that does not have sufficient attributes to form a primary key.
  • Represented by double rectangle.
  • Depends on an identifying entity set via an identifying relationship (represented by double diamond).
  • Has a discriminator / partial key (underlined with dashed/dotted line).
  • Must have total participation in the identifying relationship.
  • Primary key of weak entity = Primary key of identifying entity + Discriminator.
  • Attributes:
  • Simple vs. Composite (Address broken into City, State, Zip).
  • Single-valued vs. Multi-valued (double oval, e.g. {PhoneNumbers}).
  • Derived (dashed oval, e.g. Age derived from DOB).

# Cardinality Ratios & Table Reduction Rules

1. Many-to-Many ($M:N$):

  • Cannot merge tables.
  • Requires 3 tables: Entity $E_1$, Entity $E_2$, and Relationship table $R$.
  • Primary key of relationship table $R$ is the composite key $(PK_{E_1}, PK_{E_2})$.

2. One-to-Many ($1:N$):

  • Can be represented with 2 tables by embedding the primary key of the "1" side as a foreign key on the "N" (Many) side table.

3. One-to-One ($1:1$):

  • If one side has total participation, place foreign key in that side's table to avoid NULLs.
  • If both sides have total participation, relations can be merged into a single table.

4. Multi-valued Attributes:

  • Each multi-valued attribute requires its own separate table with $(PK_{\text{Entity}}, \text{AttributeValue})$ as primary key.

# 7. Functional Dependencies & Normalization (Bonus Week 5)

  • Functional Dependency ($X \to Y$): If two tuples agree on attribute set $X$, they must agree on attribute set $Y$.
  • Attribute Closure ($X^+$): Set of all attributes functionally determined by $X$ under given $F$.
  • If $X^+ = R$, then $X$ is a Super Key.
  • If $X$ is a super key and no proper subset of $X$ is a super key, $X$ is a Candidate Key.
  • Super Key Count Formula:

If relation $R$ has $n$ attributes and a candidate key has $k$ attributes:

$$\text{Number of Super Keys} = 2^{n - k}$$

  • Lossless Join Decomposition Condition:

Decomposition of $R$ into $R_1$ and $R_2$ is lossless if and only if:

$$(R_1 \cap R_2) \to R_1 \quad \text{OR} \quad (R_1 \cap R_2) \to R_2$$

(i.e. The intersection attributes must form a super key for at least one of the decomposed tables).

# PART 3: TOP 10 EXAM TRAPS & FORMULAS CHEAT SHEET

1. grep vs find -exec:

  • find . -name "*.txt" -exec grep -l "pattern" {} +: Efficient, spawns single grep.
  • find . -name "*.txt" | xargs grep "pattern": Standard alternative.

2. umask on files vs directories:

  • File default maximum is 666, NEVER 777. Subtraction cannot result in execution bits on files unless explicitly set by chmod.

3. Hard link deletion:

  • Deleting file does NOT delete data if hard links exist. Deleting file DOES break symbolic links.

4. Relational Algebra duplicate elimination:

  • $\pi$ (projection) eliminates duplicates by mathematical definition! In SQL, SELECT preserves duplicates unless DISTINCT is specified.

5. Foreign key NULLs:

  • A foreign key CAN be NULL unless explicitly declared with NOT NULL constraint.

6. Cartesian Product Degrees and Cardinalities:

  • Degree adds: $\text{deg}(R \times S) = \text{deg}(R) + \text{deg}(S)$.
  • Cardinality multiplies: $|R \times S| = |R| \times |S|$.

7. COUNT(*) vs COUNT(column):

  • COUNT(*) counts all rows including NULLs.
  • COUNT(col) counts only rows where col IS NOT NULL.

8. Weak entity primary key:

  • Identifying owner's PK + Weak entity discriminator.

9. sort before uniq:

  • Always pipe sort before uniq (sort | uniq -c).

10. Redirection order:

  • cmd > file 2>&1 directs stdout to file, then stderr to same destination as stdout.
  • cmd 2>&1 > file directs stderr to terminal (current stdout), then stdout to file (NOT the same!).
